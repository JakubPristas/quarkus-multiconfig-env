= Quarkus Multiconfig Extension
:toc:
:toc-title: Contents

Welcome to the documentation for the Quarkus Multiconfig extension!

The Quarkus MultiConfig extension is designed for automated processing and generation of configuration files based on a
main input file (application.properties). It enables developers to easily create environment-specific configuration
files (e.g., for dev, test, prod) in formats such as .env, .properties, and ConfigMap.yaml.

[[getting-started]]
== Getting Started

Add the following dependency to your project's `pom.xml` file:

[source,xml]
----
 <dependency>
   <groupId>org.jpristas.thesis</groupId>
   <artifactId>quarkus-multiconfig-env</artifactId>
   <version>1.0.0-SNAPSHOT</version>
 </dependency>
----

You also need to configure the extension using properties in your `application.properties` file (explained below).

[[features]]
== Features

The Quarkus Multiconfig extension allows:

* Automatic generation of environment-specific configuration files.
* Support for multiple output formats: `.env`, `application.properties`, and `ConfigMap.yaml`.
* Ability to define values per environment (`dev`, `prod`, `test`, etc.).
* Support for default fallback values if environment-specific value is missing.
* Key renaming and marking configuration variables as required.
* Automatic inclusion of variable descriptions.
* Customizable output file names and output paths.

[[configuration]]
== Configuration

The extension uses the following properties to control its behavior:

[cols="2,4",options="header"]
|===
|Property |Description

|`quarkus.multiconfig.target-environment`
|Defines the target environment (e.g., `dev`, `prod`, `test`).

|`quarkus.multiconfig.selected-templates`
|Comma-separated list of file formats to generate (`env`, `cm`, `prop`).

|`quarkus.multiconfig.cm-file-name`
|Name of the generated `.yaml` file for Kubernetes ConfigMap.

|`quarkus.multiconfig.env-file-name`
|Name of the generated `.env` file.

|`quarkus.multiconfig.properties-file-name`
|Name of the generated `.properties` file.

|`quarkus.multiconfig.output-description`
|Whether to include variable descriptions in the output files (`true` or `false`).

|`quarkus.multiconfig.output-path`
|Path where the generated files will be placed.
|===

[[input-file-format]]
== Input File Format

The input file is based on a slightly extended `application.properties` syntax.
You can define environment-specific values, fallback defaults, renamed keys, and required variables using special annotations:

* `##` - Start and end of a configuration block.
* `#` - Description for a configuration key.
* `# @<environment> <value>` - Value for a specific environment (e.g., `# @prod jdbc:postgresql://prod-db:5432/db`).
* `# @all <value>` - Fallback value if the environment-specific value is missing.
* `# @key <new_key>` - Renames the configuration key.
* `# @required true|false` - Specifies whether the variable must be uncommented.

[[example-input]]
=== Example Input

[source,properties]
----
##
# Database connection URL
# @key db.url
# @required true
# @prod jdbc:postgresql://prod-db:5432/userdb
# @dev jdbc:postgresql://dev-db:5432/userdb
# @test jdbc:postgresql://test-db:5432/userdb
# @all jdbc:postgresql://default-db:5432/userdb
##
my.database.connection=

quarkus.multiconfig.target-environment=dev
quarkus.multiconfig.selected-templates=cm,env,prop
quarkus.multiconfig.cm-file-name=ConfigMap.yaml
quarkus.multiconfig.env-file-name=.env
quarkus.multiconfig.properties-file-name=application.properties
quarkus.multiconfig.output-description=true
quarkus.multiconfig.output-path=generated-sources/config-files
----

[[generated-files]]
== Generated Output Files

Based on the example input and selected templates, the following files are generated:

=== Example `ConfigMap.yaml`

[source,yaml]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-config
data:
  #--- Database connection URL ---#
  db.url: jdbc:postgresql://dev-db:5432/userdb
----

=== Example `.env`

[source,env]
----
# !!! Uncomment and set value(s) if override is required !!!
#--- Database connection URL ---#
DB_URL=jdbc:postgresql://dev-db:5432/userdb
----

=== Example `application.properties`

[source,properties]
----
#--- Database connection URL ---#
db.url=jdbc:postgresql://dev-db:5432/userdb
----

[[notes]]
== Additional Notes

* If no environment-specific value is defined and no fallback (`@all`) is provided, the variable will be skipped.
* Generated files are placed inside the directory specified by `quarkus.multiconfig.output-path`.
* Each file type uses a different template to match its intended use case (for Kubernetes, Docker, Quarkus).
